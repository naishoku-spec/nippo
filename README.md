# 2階製造 (Production Log)

複数人で共有可能な日報管理ツールです。

## 技術スタック
- HTML5 / CSS3 / JavaScript (Vanilla)
- [Firebase Realtime Database](https://firebase.google.com/) - データのリアルタイム共有
- [Flatpickr](https://flatpickr.js.org/) - カレンダーUI

## 主な機能
- **製品名の自動引き継ぎ**: 翌営業日に前日の製品名を自動でセット。
- **カレンダー色分け**: 土曜日(青)、日曜日・祝日(赤)を自動判別。
- **モバイル対応**: スマホからでも入力しやすいカードレイアウト。
- **自動集計**: 日別・月別の生産数を自動計算。
- **データ同期**: Firebaseによる複数端末間でのリアルタイム同期。

## ローカル版の起動

1. `start-local.cmd`をダブルクリックします。
2. `http://127.0.0.1:8765/`で画面を開きます。
3. `index.html`などを直接開いた場合も、起動中のローカルHTTP版へ移動します。

ローカル版も本番と同じFirebaseのデータパスを使用します。ブラウザの保存領域は本番とは別ですが、記録の正本はFirebaseです。`index copy.html`などのコピー版やJavaScriptファイルを直接開かないでください。

## 古いデータからの保存の保護

全ページの保存では、編集の基準にしたデータとサーバーの現在値をトランザクション内で照合します。異なる場合は保存を保留し、「最新データを読み込んでください」と表示します。ボタンを押すと入力内容を保持して最新データを読み込み、入力した変更を反映します。読み込みに失敗した場合も保留中の入力は端末に残ります。

初回表示では、ブラウザが未編集の入力欄へフォーカスを戻しても、端末内の古い表示からサーバーの値へ切り替えます。入力中に受信した更新は保留し、欄を離れた後に表示へ反映します。入力した変更がある場合は、従来どおり最新値との照合を経て保存します。

新しくページを開く際には、Firebase SDKの接続失敗フラグと対象データベースの接続先キャッシュだけを退避し、接続を開始し直します。退避先は端末内の `nippo_firebase_connection_recovery` です。業務データ・未送信入力・バックアップを削除する処理ではありません。退避できない場合は接続情報も変更しません。WebSocket非対応ブラウザでは接続失敗フラグを維持します。

接続または初回データ読込が10秒以上完了しない場合は、古い表示の可能性があることを画面内に通知します。「接続をやり直す」は未送信入力を端末に保持してからページを読み直します。保持に失敗した場合は移動しません。接続・読込が回復した場合は通知を消します。`SharedSync.getConnectionStatus()` で版番号・接続状態・未完了読込数・エラーコードだけを確認でき、記入内容は含みません。

公開前に `npm run release:prepare` を実行すると、全入口ページ・共通処理・各JavaScript/CSSの読み込みURLを同じ版番号に揃えます。内容に変更がなければ番号は増えません。`npm run release:check` はファイルを変更せず、番号の不一致や公開準備後の修正を検出します。公開する際は、更新されたHTML・JavaScriptと `app-version.json` を一緒に反映してください。

古いページや異なる版の組み合わせを検知した場合は保存を停止し、再読み込みボタンを表示します。更新前の未送信入力は端末内に保持し、保持に失敗した場合は再読み込みを中止します。ブラウザの保存データやバックアップを一括削除する処理はありません。更新後も未送信入力は最新サーバーデータの読み込み確認を経て反映します。サーバー側の変更履歴は追加していません。

## 公開時に必要なファイル

画面の入口は次の4ページです。

- `index.html` + `app.js`
- `1f.html` + `1f-app.js`
- `1f-kenpin.html` + `1f-kenpin-app.js`
- `saidan.html` + `saidan-app.js`

共通で`style.css`、`1f-style.css`、`shared-sync.js`、`app-version.json`、`local-entry.js`を使用します。`local-server.js`と`start-local.cmd`はローカル起動用で、公開ページの動作やFirebaseのデータには影響しません。
