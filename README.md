# 2階製造 (Production Log)

複数人で共有可能な日報管理ツールです。

## 技術スタック
- HTML5 / CSS3 / JavaScript (Vanilla)
- [Firebase Realtime Database](https://firebase.google.com/) - データのリアルタイム共有
- [Flatpickr](https://flatpickr.js.org/) - カレンダーUI

## 主な機能
- **製品名の自動引き継ぎ**: 翌営業日に前日の製品名を自動でセット。
- **カレンダー色分け**: 土曜日(青)、日曜日・祝日(赤)を自動判別。
- **モバイル対応**: スマホからでも入力しやすいカードレイアウト。
- **自動集計**: 日別・月別の生産数を自動計算。
- **データ同期**: Firebaseによる複数端末間でのリアルタイム同期。

## ローカル版の起動

1. `start-local.cmd`をダブルクリックします。
2. `http://127.0.0.1:8765/`で画面を開きます。
3. `index.html`などを直接開いた場合も、起動中のローカルHTTP版へ移動します。

ローカル版も本番と同じFirebaseのデータパスを使用します。ブラウザの保存領域は本番とは別ですが、記録の正本はFirebaseです。`index copy.html`などのコピー版やJavaScriptファイルを直接開かないでください。

## 古いデータからの保存の保護

全ページの保存では、編集の基準にしたデータとサーバーの現在値をトランザクション内で照合します。異なる場合は保存を保留し、「最新データを読み込んでください」と表示します。ボタンを押すと入力内容を保持して最新データを読み込み、入力した変更を反映します。読み込みに失敗した場合も保留中の入力は端末に残ります。

初回表示では、ブラウザが未編集の入力欄へフォーカスを戻しても、端末内の古い表示からサーバーの値へ切り替えます。入力中に受信した更新は保留し、欄を離れた後に表示へ反映します。入力した変更がある場合は、従来どおり最新値との照合を経て保存します。

Firebase SDKの前に `firebase-storage.js` を読み込み、SDKの保存可否チェック・接続失敗フラグ・登録済みデータベースの接続先だけをページ内メモリで扱います。記録、未送信入力、バックアップ、他のFirebaseプロジェクト、sessionStorageの保存方法は変えません。保存容量が埋まった後でも、SDKの接続処理が保存エラーで停止しないための処理です。以前から端末内にある接続情報や `nippo_firebase_connection_recovery` も削除しません。

接続または初回データ読込が10秒以上完了しない場合は、古い表示の可能性があることを画面内に通知します。「接続をやり直す」は未送信入力を端末に保持してからページを読み直します。保持に失敗した場合は移動しません。接続・読込が回復した場合は通知を消します。`SharedSync.getConnectionStatus()` で版番号・接続状態・未完了読込数・エラーコードだけを確認でき、記入内容は含みません。

接続が復旧しても、端末内の保存容量そのものは増えません。未送信入力を端末内に保存できない間は画面内で保持し、長時間残る場合は警告、通常のページ移動・終了時には確認を出します。サーバー保存が完了すると保護を解除します。端末やブラウザの強制終了時まで保持できる保証はありません。

離脱確認は実入力の保護に限ります。同じ値の再保存や自動生成した空行だけでは警告しません。未送信入力の内容と編集基準が既存の端末内コピーに一致する場合は、管理情報の再保存に失敗してもそのコピーで保護できると判定します。他タブの異なる入力や、コピーにない新しい変更は同一視しません。古い保存内容をサーバーへ反映する際の最新値照合は維持します。進捗管理の列色は表示だけで補完し、閲覧時や未変更の列名から不要な保存を発生させません。

ブラウザ標準の離脱確認の文言はサイト側で変更できません。未保存入力のページ内警告には、入力が消える危険、確認画面では「キャンセル」を押すこと、保存が終わるまで画面を閉じないことを表示します。通常は10秒後に表示しますが、離脱を試みた場合はすぐページ内にも表示し、キャンセル後に案内を読めるようにします。保存後は自動で消します。

公開前に `npm run release:prepare` を実行すると、全入口ページ・共通処理・各JavaScript/CSSの読み込みURLを同じ版番号に揃えます。内容に変更がなければ番号は増えません。`npm run release:check` はファイルを変更せず、番号の不一致や公開準備後の修正を検出します。公開する際は、更新されたHTML・JavaScriptと `app-version.json` を一緒に反映してください。

古いページや異なる版の組み合わせを検知した場合は保存を停止し、再読み込みボタンを表示します。更新前の未送信入力は端末内に保持し、保持に失敗した場合は再読み込みを中止します。ブラウザの保存データやバックアップを一括削除する処理はありません。更新後も未送信入力は最新サーバーデータの読み込み確認を経て反映します。サーバー側の変更履歴は追加していません。

## シフト表

表で早番・遅番の名前を選び直しても、ほかの週は変わりません。全体の順番を変えるには、メンバー管理で並べ替え、適用開始週と回し方を選んで青いボタンで確定します。カレンダーでは今週の月曜日から200年先までのどの日でも選べ、選んだ日がある週の月曜日から新しい順番を適用します。確定するまでは担当に反映されません。

どちらの回し方でも、早番は左端の人から順番に進みます。「遅番 → 早番」では最初の遅番は左から2人目で、次の当番週ではその人が早番になります。「早番 → 遅番」では最初の遅番は右端の人で、次の当番週では最初に早番だった人が遅番になります。回し方が保存されていない既存の設定は「遅番 → 早番」のままです。

早番・遅番がない週は、日付欄の「早番・遅番なし」を選びます。その週は順番を進めず、次の当番週へ繰り越します。手動で設定した担当、通常シフト、備考は消えません。新しい順番の開始週が「なし」の場合は、次の当番週が新しい順番の1週目になります。

新しい順番は、開始週以降の確定済みの早番・遅番や、先に設定した開始週のルールにも優先します。それより前の週と、日付・通常シフト・備考は変更しません。確定後に表で担当を変えた場合は、その週だけに反映します。

青い「変更後の順番を確認」ボタンは、休みの週を含め、全員が1度ずつ早番になるまでの予定と、切り替え対象の手動設定を表示します。プレビューの「確定」を押すまでは順番を保存しません。表示中に共有の設定が変わった場合は、最新の内容でプレビューを開き直してください。

表の下では、就業時間、時間差昼休憩の順に、早番・中番・遅番の開始と終了を編集できます。変更した時刻だけがシフト表の共有設定に保存され、当番や日報の時刻は変更されません。遅番の昼休憩は初期状態では未設定です。

通常シフトの欄は表示せず、その幅を備考欄に充てています。保存済みの通常シフトの値は保持し、備考などの編集でも上書きしません。

## バックアップ

ブラウザ内の日付別バックアップと直近3件の履歴は新規作成・更新しません。すでに残っている控えは、保存した端末・ブラウザで同じサイトの `index.html?view=backup` を開くと確認できます。メニューからは非表示です。

PCのバックアップは、Windowsタスク スケジューラの `Nippo-Weekday-Backup` で平日の正午（日本時間）に実行します。PCが起動してユーザーがサインインしている必要がありますが、ブラウザやCodexを開く必要はありません。スクリプトは日本時間で土日と正午前を除外します。日報側とシフト表側のアプリ用データを読み取り専用で取得し、開発用のデータを除いて、両方が揃った場合だけOneDrive外のユーザーフォルダの「日報バックアップ」に日付付きJSONを新規作成します。同じ日のファイルを上書きせず、過去のファイルも削除しません。

同じ日付のファイルが破損している場合は元のファイルを残し、正常な控えを `nippo-backup_YYYY-MM-DD-2.json` のような連番付きの名前で保存します。保存の確定前にも日本時間の日付を確認し、処理中に日付が変わった場合は控えを確定しません。

実行結果はタスク スケジューラ、またはインストール先の `%LOCALAPPDATA%\NippoBackup\backup.log` で確認できます。PC用の `tools/weekday-backup.cjs` とバックアップのJSONは公開ファイルに含めないでください。

## 公開時に必要なファイル

画面の入口は次の4ページです。

- `index.html` + `app.js`
- `1f.html` + `1f-app.js`
- `1f-kenpin.html` + `1f-kenpin-app.js`
- `saidan.html` + `saidan-app.js`

共通で`style.css`、`1f-style.css`、`shared-sync.js`、`firebase-storage.js`、`app-version.json`、`local-entry.js`を使用します。シフト表には`shift-rotation.js`、`shift-preview.css`、`shift-hours.js`、`shift-hours.css`も必要です。`local-server.js`と`start-local.cmd`はローカル起動用で、公開ページの動作やFirebaseのデータには影響しません。
